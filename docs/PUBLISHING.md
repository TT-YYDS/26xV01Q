## 完成后检查顺序

遵守根目录 `AGENTS.md` 的空闲证明、内容审查、快照测试和非强制更新条件。当前任务仍在运行这一事实并不要求它先结束，但必须已停止业务编辑，并确认不存在其他本项目写入者。只看到部分任务状态时不能推断全项目空闲。

1. 检查项目说明、任务状态、工作区、索引、remote、当前分支及提交历史。初次发布没有本地 Git 历史时明确记录，不导入无关目录的历史。
2. 对白名单内每一文件审查凭据、隐私、客户数据及第三方内容。把允许文件复制到独立快照，记录路径、大小和 SHA-256；不从活动目录边读边上传。审查报告和日志保存在被忽略的 `tmp/` 下。
3. 在快照内运行适用测试，确认测试所用代码与待发布内容一致。比对快照和工作区；测试生成物不得加入发布树。失败、文件改变或空闲证据过期均跳过本次发布。
4. 核实已有连接器账号为 `TT-YYDS`。同名仓库如已存在，先审查来源、全部树和历史；无法确定关系时停止。新建仓库需通过获授权的创建流程，不能另行申请凭据。
5. 以已审查远端 `main` 头提交为父提交创建快照提交，保留无关远端贡献；发现未知贡献就停止协调，不能自动合并或删除。更新引用时传入预期旧 SHA 且禁止强推。远端头改变时停止，不盲目重试。
6. 读取新远端头、递归树和文件，逐个比对发布清单及 Git blob 哈希，排查额外文件；再通过匿名公开访问核实仓库。记录提交 SHA、测试结果、排除范围和限制。
