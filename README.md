# 26xV01Q：点云拼接、侧面截面与 CAD 偏差分析

本项目使用 Python + PySide6 原生桌面界面完成点云拼接、法向截面和 CAD 偏差分析。软件支持手动流程和自动流程；自动流程复用手动流程保存的输入源、主轴区域、点云参数、DXF、配准路径和测量路径。左侧固定显示六个流程入口，右侧只有一个显示区域。点云、截面、审核、CAD、表格按当前选择切换，不采用整页上下滚动。Qt WebEngine 仅作为离线 Plotly/WebGL 画布，不再嵌入 Streamlit 网页，也不启动 HTTP 服务。CAD 只能拟合已经冻结的最终截面，不反向调整点云坐标。

## 启动

```powershell
cd D:\TT\26xV01Q
```

## 客户端界面

- 数据：手动流程选择点云输入目录，或选择 3D 相机传输后的落盘目录；自动流程按已保存模板扫描完整点云组。
- 点云：参考点云、融合点云、表面预览；预览精度、去噪和点径。
- 截面：框选主轴后生成三维法向平面；切片预览、最终截面、原始截面（基线）、邻域诊断。
- 拼接：处理当前组，或依次处理已确认工位且各自已框选主轴的组。
- 审核：不同颜色区分来源，四视图或单视图切换，配准指标与质量判定。
- CAD：导入 DXF、连续路径/单段选择、配准与测量、来源与代表线、偏差曲线、结果表。

CAD“来源与代表线”合并显示来源分色的最终截面、CAD 原图和测量代表线，
各来源、CAD 参考及各代表线均可通过图例独立显隐。代表线连接报告 CSV 中各有效站位的局部中位数代表点，
与计算平均 X/Y 偏差使用的采样点一致，不是按全路径均值整体平移 CAD。
无效站位断开，不插值补齐；来源点和 CAD 适度淡化，悬停显示来源坐标或站位及法向/X/Y 偏差。
当前 CAD 原图坐标系报告无需重新测量，旧坐标系报告或缺少站位 CSV 时需重新测量。

参数使用分类分页对话框，可导入/导出 JSON；日志单独打开；结果表按页切换。
手动计算在后台线程串行运行，预览有小容量缓存；自动批次按 CPU、可用内存和数据量
选择 1～4 个独立进程，并限制每进程计算线程数。取消会等待当前算法阶段结束，不强杀进程。
显示采样只影响预览，不改变正式融合和截面点云。历史数据未确认采集关系时只能作为参考。

手动流程完成主轴框选、DXF 导入、配准路径和测量路径后，会持续更新
`settings/workflow_profile.json`；也可以在“数据”页显式点击“保存自动模板”。
软件每次启动固定进入手动流程，即使上次退出时处于自动流程，也不会自动监听或处理。
启动时仍会加载已保存的参数、主轴区域和 CAD 模板，供用户确认、调试和修改；只有
用户点击顶部按钮切换到自动流程后，软件才使用该模板监听输入目录：直接放在目录中的 5～8 个 PLY
视为一组，子目录中的 5～8 个 PLY 分别视为多组。文件需要至少稳定 1 秒，传输中的
文件和不完整组会等待下一次扫描。每组自动完成点云拼接、截面提取、CAD 配准、偏差
和角度测量；同一组文件指纹不变时不会重复处理。当前“3D 相机传输”接口采用相机
输出 PLY 的落盘目录，也可使用左侧“相机采集”直接调用盛相 SDK。

顶部使用加大的“手动流程 / 自动流程”点击切换按钮，不再使用下拉框。
自动运行有独立的累计计时、批次完成数、预计剩余时间、预计完成时刻和进程/线程数显示；
预计值基于最近历史/当前已完成组的实际耗时，首组完成前显示“首组完成后计算”。切回手动或点击停止后，
不再派发后续组，已完成结果仍保留。CAD“测量结果”在自动模式下汇总本次软件会话的
所有自动组次，显示组名/批次、质量、测量路径、平均 X/Y 偏差和角度差；平均法向偏差
及每组耗时仍记录在报告中，不在汇总表显示。同名组重新采集后以新组次保留，失败和取消也有独立记录。
每次从手动流程重新点击切换到自动流程都会清除当前自动会话的汇总和去重状态，
因此相同点云也会重新测量并输出新的批次；历史自动输出和原始点云保留不变。
每个自动批次会保存 `outputs/automatic/<批次>/batch.json`，各组报告追加运行耗时及资源记录；
表格在小窗口下支持横向滚动，分页行数随窗口高度调整。自动完成不会用输出目录的冻结 DXF
覆盖手动模板。

自动流程扫描到多个完整点云组后，会按当前机器的 CPU、可用内存和组数量自动分配独立进程，
同时处理多个组；每组仍使用保存的自动模板和自己的输入文件，完成后分别回写对应组结果。
手动流程只负责确认、调试和保存模板，不显示并行处理按钮。

详细说明与验证入口见 `docs/NATIVE_DESKTOP.md`。

## 保留的处理链

1. 读取 `media/<组名>` 内的 5～8 个 PLY 点云；5/6 个视角按固定工位顺序恢复采集视角，其他数量走标定块 ROI 初始定位。
2. 对每个点云进行体素化和离群点去噪。
3. 仅使用各视角中的多面体标定块 ROI 进行初始刚体配准；7/8 个视角也不使用工件全云做 FPFH/RANSAC。
4. 对已定位视角仅使用标定块建立多视角闭环位姿图，限制旋转和平移修正范围，避免多面体对称面造成错配；工件点云只做质量诊断，不反向修改位姿。
5. 固定位姿后，从每个原始全分辨率点云提取多张薄截面。
6. 仅在两个工位的共同横向覆盖区域比较轮廓：标准方案以 0.115 mm 的局部 P90 阈值诊断持续错层、重影、非平行轮廓错配或明显偏移。覆盖优先模式默认不因不重叠、局部轮廓差异或互补覆盖而剔除工位，也不删除其独有点；只有标定块质量不合格、位姿不可靠的工位才退出融合。
7. 使用所有标定块质量合格的原始全分辨率点云按固定刚体位姿重新融合。标定块 ROI 只用于求位姿，默认从最终被测件融合云中隔离；去噪和融合的体素内只选择一个真实测量样本，不再输出坐标平均值；只被一个视角看到的体素仍保留。融合完成后仅清理小型、紧凑、弱支持且与主体断开的孤立组件，再从该融合云直接导出截面，截面本身不再做统计或连通域清噪。
8. 在客户端 CAD 入口导入 DXF，选择 1 条连续配准路径和 1 条或多条测量路径；单条线段可通过“单段”确认。CAD 只拟合固定截面；每条测量路径分别生成法向偏差和角度结果。

## 截面审核与输出

### 自动流程位姿参考

自动会话从首个完成完整处理且标定块、闭环连通性及拼接质量检查通过的组，
冻结该组各视角的旋转和平移作为后续组的初值。后续仍用本组标定块精配准，
保留闭环、重叠检查、融合和 CAD 测量；参考匹配或精配准检查失败时走原完整搜索。
本组拼接质量复核失败会完整重算，并保留参考尝试的诊断。机器人重复性数值
不作为测量误差或验收门限；CAD 覆盖率不足仍如实报告，不因复用位姿而变成合格。

现场建议按 `view_1.ply`、`view_2.ply` 等编号，或在每组目录提供
`station_order.json`：`views` 数组每项含 `file` 和 `station`，覆盖全部 PLY，
每个位置编号唯一且跨组一致。该编号表示机器人拍摄位置，不是文件排序号。
无编号的旧数据仅在原生坐标系下的标定块几何可以明确区分视角时尝试对应，
歧义时不复用；不按文件名随机主干或修改时间猜测位置。

位姿参考只在同一自动会话内保留，重新进入自动模式会清空；
配置或输入源变化会失效。后续组不会覆盖首个参考，避免逐组累积漂移。
始终保留组级多进程并行，不为等待参考而闲置其它进程；已派发组继续处理，
参考建立后供尚未派发组和后续批次使用。`run_summary.json` 的 `pose_reference`
记录匹配方式、各视角快速路径是否通过及耗时；学习来源保存在批次的
`pose_reference.json`。这些初值不是另一组的测量数据。

隔离真实数据对照入口：
`tools/verify_pose_reference.py --groups 1 2 3 4 --rounds 1 --threads 3`。
结果写入 `tmp/pose_reference_verification`，不覆盖正式历史输出。

每次处理会在 `outputs/<组名>/<时间戳>/` 写入：

- `merged_pointcloud.ply`：标定块质量合格视角的原始全分辨率目标点云按刚体位姿融合后的最终点云。
- `vertical_section_raw.png` / `.ply`：直接从已完成孤立组件清理的融合云提取的基线截面；不是融合清理前的截面，不执行截面后置清噪。
- `vertical_section.png` / `.ply`：当前流程冻结的最终截面，直接来自已完成融合云孤立组件清理后的点云；不会再次删除截面点或修改坐标。
- `section_alignment_audit.png`：逐工位薄截面质量诊断图；覆盖优先模式下红色只表示标定块质量闸门未通过，截面不重叠本身不会标红剔除。
- `alignment_audit.png`：按扫描来源着色的标定块位姿叠加审核图。
- `run_summary.json`：位姿、截面质量诊断、标定块闸门状态、完整运行参数，以及 `section_integrity` 缺口来源诊断。

`run_summary.json` 的 `section_consensus.whole_cloud_fusion` 还会记录标定块隔离是否生效、排除余量和被隔离点数。`calibration_exclusion_applied=true` 表示标定块只参与位姿计算，不进入最终测量云；如果现场需要排查 ROI，可临时关闭该开关，但正式 CAD 测量应保持开启。

运行摘要中的 `section_consensus.whole_cloud_fusion` 记录全云体素融合证据，包括多视角支持体素、单视角独有体素、每个来源视角保留的体素数和代表点残差。`coordinates_averaged=false` 表示输出坐标来自真实采样点，而不是多个视角的均值。

截面审核图中，`通过` 表示待验工位在共同覆盖区内与可信工位贴合；`局部覆盖` 表示没有足够的共同区域可判断；`仅诊断` 表示发现错层、重影或额外轮廓证据，但在覆盖优先模式下仍保留该工位的完整目标点云。截面诊断只记录风险，不根据共同区域的差异删除互补视角，也绝不根据截面或 CAD 回写、旋转、平移或重排点云。

处理链会比较 `vertical_section_raw` 基线截面与最终截面的结构。当前最终截面是基线截面的副本，两者都来自清理后的融合云，因此 `stable_after_cleanup` 只说明这两个截面结构一致，不能单独证明融合清理无损；清理影响需另行结合组件记录和源点云复核。如果仍看到断口，应检查扫描覆盖和截面位置。客户端“截面 / 邻域诊断”只读扫描平行平面；修改下一次处理偏移需要在截面参数中明确设置。框选默认关闭自动偏移，避免算法替换选定中心。程序不会通过增厚、插值、连线或 CAD 反向调整补造测量点。

## 盛相相机接入

原生客户端左侧“相机采集”接入 `盛相SDK/02_Binary/02_SizectorS_API/x64/`
的 Sizector S C API 2.776，不执行供应商示例，不依赖 OpenCV 或 .NET。
只在点击搜索/连接后加载 SDK，启动软件不会自动连接或拍摄。

1. 接好相机，在“相机采集”中搜索并选择设备。首次使用如搜索失败，检查
   SDK `04_Driver` 中的相机驱动和 USB 连接；程序不会自动安装驱动。
   本机 Windows 11 x64 已于 2026-10-12 安装随包 `04_Driver/Win10/x64/cyusb3.inf`。
   设备管理器通用名称可能为 Cypress FX3 USB BulkloopExample Device，实际型号和
   序列号以 SDK 搜索结果为准。新机器需要管理员安装匹配驱动，不应禁用签名检查。
2. “采集设置”可选 3D 模式、超时、SDK `.mpset` / `.xml` 参数文件和输入目录。
   “曝光设置”勾选“自定义曝光”后可改曝光模式、次数、三档 3D 曝光强度、灰度图
   曝光强度、用户增益及 HDR/PHDR 参数；相关字段按模式启用。强度范围 0.1～100，
   是 SDK 曝光强度，不是毫秒。未勾选且未指定参数文件时保留设备当前曝光。
   连接时先加载参数文件，再应用已启用的自定义曝光；使用软件触发和浮点 3D 输出。
   修改后可直接点击“应用并采集视角”：先下发并回读曝光，确认成功后再取像。
   也可单独点击“应用曝光”或“保存设置”；下发失败不触发拍摄，保留已采视角。
   直接采集只应用设备参数，需要下次打开仍保留设置时应点击“保存设置”。
   同一组内可在采集间隙继续调整曝光；拍摄/应用参数进行中禁用编辑。
   输入数值后按 Enter 只确认该值，不自动执行相机命令。
3. 每组 5～8 个视角，默认 5 个。按现有工位角度和顺序逐次拍摄，保存为
   `1.ply`～`5.ply`（视角数不同则相应增减）。软件不控制转台，不自动推断
   拍摄角度；工位顺序、相机坐标系和尺度需与现有自动模板一致。
4. 采集窗口显示灰度预览、有效点数、分辨率和耗时。采满后“完成并导入”：
   手动模式导入文件列表，自动模式交给已有拼接、截面和 CAD 测量流程。
   自动运行时采集目录固定为当前监听目录，可继续采集下一组。
5. “保存设置”保存页面全部设置，包括设备、SDK/参数/输入目录、组名、模式、超时、
   视角数及曝光。未连接时可保存，下次打开恢复；连接成功和整组发布仍会保存偏好。
   设置保存到 `settings/workflow_profile.json` 的 `camera` 字段，不改原有 CAD/点云模板。
   已连接时保存会先应用待确认曝光，失败不提示保存成功。参数文件旁的保存图标可导出
   当前相机完整 `.mpset` / `.xml`，拒绝覆盖已有文件；不写相机默认参数、标定或固件。
   旧版无版本号的默认 6 视角会迁移为 5；新版明确保存的 6/7/8 视角会保留。

采集只按 SDK 掩码低三位和有限坐标筛除无效点，保留 HDR 有效点和真实毫米
坐标，不变换、不缩放、不补点；PLY 为二进制 XYZ + uchar 灰度 RGB。
未完成组暂存在输入目录旁的 `.<目录名>_camera_pending/<会话>/`，不会被当前
输入目录扫描；整组完成后用目录重命名发布，拒绝覆盖已有组或视角。
组内 `camera_capture.json` 记录设备序列号、模式、时间、触发编号、点数和设置。
`capture_settings` 是组开始时的页面设置；各视角的 `exposure_settings` 单独记录
对应 SDK 帧头中的曝光配置，组内调参不会把旧视角记录改成新参数。
自动 HDR 推导出的每次实际曝光强度尚未额外导出，不能把配置值当成其计算结果。
结束组或关闭窗口会保留暂存文件，可手动复核/恢复；不自动删除或恢复半组。
关闭时等待当前 SDK 操作结束，再关闭设备并删除实例；没有强杀采集线程。
实时 `Snap` 帧借用相机内部缓冲，复制坐标/图像后由 SDK 管理其生命周期；
只有 `Utils_Load` 分配的离线帧由调用方释放，避免实时采集后关闭时重复释放。
相机偏好保存在自动模板的可选 `camera` 字段，不替换原有点云/CAD 参数。

本机已从随 SDK 提供的 VC++ 2012 x64 安装包提取三项运行库到
`settings/sizector_runtime/x64/`，没有运行安装程序或修改系统注册表。

## 项目结构

- `docs/POINTCLOUD_SOFTWARE_DESIGN.md`：点云拼接、截面测量和 CAD 对比的总体设计基线、删除/重写边界及后续优化路线。
- `app.py`：统一网页入口、点云参数和结果展示。
- `desktop_client.py`：原生客户端启动入口。
- `pointcloud_app/native/`：单显示区窗口、后台任务、离线画布、参数对话框和客户端适配层。
- `pointcloud_app/sizector_camera.py`：盛相 C API、帧内存管理及完整采集组发布。
- `pointcloud_app/desktop_runtime.py`：工位映射辅助逻辑，兼容保留旧网页服务辅助函数。
- `pointcloud_app/cad_geometry.py`：独立于界面的 CAD 路径拓扑与选择。
- `pointcloud_app/profiles.py`：网页和客户端共享的数据组参数方案。
- `pointcloud_app/pipeline.py`：去噪、标定块配准、截面审核、原始点融合和输出。
- `cad_analysis_panel.py`：第 8 步同页 DXF 选择、CAD 拟合和偏差报告。
- `media_analysis_core.py`：CAD 配准、逐测量线法向偏差/角度计算和报告生成。
- `tests/`：截面几何、GPU 回退、交接和预览测试。

运行输入、输出和网页运行文件分别位于 `media/`、`outputs/` 与 `web_runs/`，不会与程序源代码混在一起。
